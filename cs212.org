** wishful solution

This boils down to an optimization problem: given a list of poker hands, find the hand that has the highest value.

\[\textrm{argmax} \, _{h \in H } \, \textrm{rank}(h) \]

This can actually be solved elegantly with the =max= function in Python.
When =max= is called with an iterable, it returns the maximum element in the iterable; but when an extra =key= argument is specified, =max= returns the element that maximizes the =key= function.
(Basically, we can take =key=None= to be using the identity function.)

def poker(hands):
    "Find the hand with the highest rank."
    return max(hands, key=hand_rank)

def hand_rank(hand):
    "rank a poker hand."
    ranks = card_ranks(hand)

    if straight(ranks) and flush(hand):
        return (8, max(ranks))
    elif kind(4, ranks):
        return (7, kind(4, ranks), kind(1, ranks))
    elif kind(3, ranks) and kind(2, ranks):
        return (6, kind(3, ranks), kind(2, ranks))
    elif flush(hand):
        return (5, ranks)
    elif straight(ranks):
        return (4, max(ranks))
    elif kind(3, ranks):
        return (3, kind(3, ranks), ranks)
    elif two_pair(ranks):
        return (2, two_pair(ranks), ranks)
    elif kind(2, ranks):
        return (1, kind(2, ranks), ranks)
    else:
        return (0, ranks)

from collections import Counter

def kind(n:int, ranks):
    """Return the first rank that this hand has exactly n (1, 2, 3, 4) of.
    Return None if there is no n-of-a-kind in the hand."""

    c = Counter(ranks)
    res = [k for k, v in c.items() if v==n]
    return res[0] if res else None

def two_pair(ranks) -> tuple[int] | None:
    """If there are two pair, return the two ranks as a
    tuple: (highest, lowest); otherwise return None.

** ace-low straight

We actually have a bug in our poker function, which is related to the ace-low straight hand.

#+begin_src python :results output
als = "AS 2S 3S 4S 5H".split()  # ace-low straight hand
print(als)

#+RESULTS:
: ['AS', '2S', '3S', '4S', '5H']
: ['2S', '2H', '2C', '7D', '8S']
:
: (0, [14, 5, 4, 3, 2])
: [14, 5, 4, 3, 2]

It's the smallest straight, but a straight nevertheless, so it should have higher ranks than all the three of a kind hands.
However it's not the case, and our poker function takes the three of a kind as the higher ranked hand.
The reason is that it's not being regarded as a straight.
Since A has rank 14, we are simply looking a hand with ranks =[14, 5, 4, 3, 2]=, just a high card hand.

So we need an exception: when the card appears in an ace low straight hand, A has rank of 1 rather than 14.
The key question is: what should we change now?

For this question the answer is relatively simple.
Although the bug has multiple consequences, all of them follow a single causal chain: the =card_ranks= of Ace should be 1 instead of 14 in the ace-low straight, causing the failed =straight= check, and as a result the hand is recognized as a high card suit rather than a straight, which leads to =hand_rank= returning the wrong result, and =poker= picking the wrong hand.
So we just need to deal with the exception in =card_ranks=, and everything follows should work correctly.

#+name: poker-card-ranks-fix
#+begin_src python :results none
def card_ranks(cards) -> list[int]:
    """Return descending list of integer ranks for a hand of cards."""
    ranks_str = '--23456789TJQKA'

    ranks = [ranks_str.index(r) for r, _ in cards]
    ranks = sorted(ranks, reverse=True)

    if ranks == [14, 5, 4, 3, 2]:
        ranks = [5, 4, 3, 2, 1]
    return ranks
#+end_src

** breaking ties

A second edge case is ties, that is, what happens when multiple hands have the same ranking. At present when that happens, we simply choose the first hand that has the maximum ranking, because that's just how the builtin =max= function works.
But this doesn't feel fair, especially for the other players with another winning hand of the same ranking.

#+begin_src python :results none
def allmax(iterable, key=None):
    "Like max, but return all arguments with the maximum value."
    key = key or (lambda x: x)
    m = max(key(x) for x in iterable)
    return [x for x in iterable if key(x)==m]


def poker(hands):
    "Find the list of hands with the highest rank."
    # filter out invalid hands
    return allmax(hands, key=hand_rank)

def validate(hand) -> bool:
    "Check if the given hand is valid."
    suits = set(c[-1] for c in hand)
    ranks = set(c[0] for c in hand)

    is_proper_hand = (
        len(hand) == 5                              # 5 cards
        and len(set(hand)) == 5                     # each card is unique
        and sum(len(c)==2 for c in hand) == 5       # each card has two characters
        and suits.issubset(set('SHCD'))             # second char in the four suits
        and ranks.issubset(set('23456789TJQKA'))    # first char in the 13 ranks
    )

    return is_proper_hand

import random

def deal(numhands, n=5):
    "Return a list of numhands hands, each with n cards."
    deck = [r+s for r in '23456789TJQKA' for s in 'SHDC']
    random.shuffle(deck)
    return [deck[i*n:(i+1)*n] for i in range(numhands)]

** shuffling hands

We simply called =random.shuffle= to shuffle the cards before dealing. If we are so inclined we can also write the shuffling function ourselves. However, being a function used to "randomize" the card ordering, we have to guaranttee the randomness. But how? This is something we should consider ever before implementing the shuffling algorithm.

It's not enough to just look at one shuffled deck, we have to check their distributions. "All cards are random, but some are more random than others."

**** Norvig teacher's shuffling

We can simply keep swapping the cards till all of them are swapped at least once. To achieve this we can try a brute-force approach, keep a list of swappedness of all cards, and simply keep swapping till all the values are true.

**** Norvig and Knuth's shuffling

A second implementation is more methodical: starting from the first card, we swap it with some random card following it, and keep repeating it till we reach the penultimate card.

**** Verifying soundness of shuffling algorithms

Our goal for shuffling is true randomness: we want each permutation of the deck to be equally likely to appear. Just by inspecting the shuffling logic it's hard to see whether an algorithm has reached this true randomness, but it's easy to verify it, if we have shuffled a sufficient number of decks, because this problem has a clearly verifiable result.

This is one of these common cases where, computers, being exceptionally good at repetitive tasks, can help ease our burden in solving logically difficult problems.

The first program is inefficient, which is unfortunate enough, but more importantly it's wrong.
